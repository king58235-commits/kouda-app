# 每日飲食扣打（kouda-app）

手機優先的離線 PWA：常吃的食物點一下就記，當場知道今天還剩多少熱量、蛋白質還差多少。
**App 是唯一帳本；ChatGPT 只負責估算陌生餐點與提供建議。** 不登入、不連雲端、不接任何 AI 服務。

- 純靜態網站（原生 HTML／CSS／JavaScript），資料存在手機瀏覽器的 IndexedDB。
- 沒有網路也能打開、也能記錄（已實測：關掉伺服器後重新整理，畫面與資料都在）。
- 手機和電腦**不會自動同步**；靠「備份檔」搬資料（見下方）。

## V1.1 新功能（2026-10）

操作更快、更少步驟；資料格式與備份**完全不變**（可直接從 V1 升級，舊備份照常還原）。完整說明與截圖見 [docs/V1.1-操作說明.md](docs/V1.1-操作說明.md)，驗收與相容性見 [docs/V1.1-驗收報告.md](docs/V1.1-驗收報告.md)。

- **快捷卡片 ＋／−**：點卡片主區記一份；右上角「−」減一份。減號只動你單獨記下的份數，不會動到套餐裡的組成；套餐的減號一次拿掉最近的一整組。
- **左滑刪除**：今日清單往左滑刪除（短滑露出刪除鈕、滑到底直接刪除），都有「撤銷」。
- **動畫與首頁整理**：卡片回饋、+1／−1、數字與進度條平滑變化、清單進退場、面板滑入滑出；標籤區分「套餐／選份量／待確認」；尊重「減少動態效果」。
- **最近／常吃**、**複製舊餐**（用原紀錄快照）、**把今天的組合存成套餐**、**食物庫搜尋**。

## 1. 在電腦上試跑（需要 Node.js 20 以上、Python 3）

```bash
npm test
```

```bash
npm run serve
```

然後用瀏覽器開 <http://127.0.0.1:8765/>。第一次會看到「匯入初始食物清單」，選 `private/seed.json` 即可。

| 指令 | 作用 |
|---|---|
| `npm test` | 跑全部自動測試（含私人資料外洩檢查、V1 備份相容性） |
| `npm run serve` | 本機測試伺服器（埠 8765，只開 `app/`） |
| `npm run check-seed` | 檢查 `private/seed.json` 並印出食物、套餐現算總數、快捷格排列 |
| `npm run stamp` | 改了 `app/` 底下任何檔案後必須執行：更新離線快取版本（`npm test` 會提醒） |
| `npm run icons` | 重新產生 PWA 圖示 |

## 2. 手機第一次使用（Android）

### 2-1. 把初始食物清單傳到手機（一次就好）
初始食物清單是 `private/seed.json`（11 項食物、3 組套餐、1800 kcal／110 g／05:00 換日、12 格快捷鍵）。
**它不在公開網站裡，也不在 GitHub 上**，所以要自己傳到手機，任選一種：

- 用 LINE 的「Keep 筆記」或「傳給自己」傳 `seed.json`
- 放進 Google 雲端硬碟（或寄電子郵件給自己），在手機上下載
- 用 USB 線複製到手機的「下載」資料夾

### 2-2. 匯入
1. 手機 Chrome 打開網站（網址見第 6 節），第一次會出現「匯入初始食物清單」。
2. 按「匯入初始食物清單（選擇檔案或貼上）」→ 按「選擇檔案」→ 選剛才存好的 `seed.json`。
3. 看到「檢查通過：食物 新增 11、套餐 新增 3」→ 按「匯入並開始使用」。
4. 選不到檔案？打開 `seed.json`，全選複製內容，貼到畫面上的「或貼上檔案內容」框，效果相同。

匯入後所有資料都在這支手機裡，之後離線也能用。

### 2-3. 加到主畫面
Chrome 右上角 ⋮ →「安裝應用程式」或「加到主畫面」。之後從桌面圖示開啟，像一般 App。

## 3. 每餐怎麼用

| 想做的事 | 操作 |
|---|---|
| 記一份常吃的 | 點一下快捷格（格子右上角的 ×N 是今天已記幾份）。底下會出現「撤銷」。連點同一個食物會加份數 |
| 一次記一整組套餐 | 點 ★ 套餐格；會展開成單品，清單裡可以點開，只改其中一項（例如茶葉蛋 2 顆改 1 顆），或整組刪除 |
| 滷味／自助餐／早餐店（▾） | 點一下 → 選偏少／一般／偏多 |
| 份數不是 1 | 長按快捷格 → 選 0.5／1／2 或自訂份數；或在清單點那一筆 → 改份數 |
| 不知道精確數字的外食 | 下方「＋ 粗估」→ 只填熱量就能記；蛋白質不填＝未知（不會當 0）。可勾「存成快捷食物」 |
| 改／刪／移到別天 | 清單每一筆右邊的「⋯」。刪除都能在 6 秒內按「撤銷」 |
| 凌晨補記或記昨天 | 頂端 ‹ › 切換日期；0:00–5:00 之間畫面會明確寫「正記入 10/20」並提供一鍵改記另一天 |
| 看超標 | 剩餘變成紅字「已超過目標 N kcal」，不會顯示負數也不會歸零 |

首頁最上方永遠只有一個大數字：**今天還剩多少 kcal**。下面是已記／目標、蛋白質（已記錄的估算值／目標，另有幾項未知）。

## 4. 跟 ChatGPT 來回

**問 GPT（App → GPT）**：按「複製給 GPT」→ 選「晚餐建議／估算這餐／自由提問」→ 按「複製」→ 到 ChatGPT 貼上。
複製的內容包含：飲食日、現在時間、目標、已記、剩餘、蛋白質與未知項數、每一筆的完整名稱／份數／熱量／蛋白質／來源，並明確告訴 GPT「App 是帳本，請沿用這些數字，不要另立帳本」，以及回覆格式。

**把 GPT 估的餐點記回來（GPT → App）**：
1. 請 GPT 用這個格式回覆已吃的餐點（`複製給 GPT` 的內容已附上格式說明）：
   `@扣打 餐點完整名稱｜熱量 600-740 kcal｜蛋白質 23 g｜備註`（蛋白質未知寫「未知」）
2. 在 GPT 複製整段回覆 → App 按「貼上 GPT」→「讀取剪貼簿」（或手動貼）。
3. 只會讀取 `@扣打` 開頭的行，放進**待確認清單**：可以取消勾選、改名稱、選偏少／一般／偏多、勾「存成快捷食物」。
4. 按「記入今日（N 項）」才會寫進帳本。**沒按就不會改變任何數字。**

安全規則：GPT 的「候選建議」不是已吃，不會被記入；格式錯誤、負數、不合理的數字會被拒絕並說明原因；今天已經用同一行記過的會警示並預設不勾；同一個確認卡按兩次不會重複記入；範例格式行貼回來也不會變成紀錄。

## 5. 備份與還原（請先看這段）

**資料只存在這支手機的瀏覽器裡。清除瀏覽器資料、解除安裝、換手機，紀錄都會消失。** 手機和電腦也不會自動同步。

### 備份
設定 → **下載備份檔**（檔名 `kouda-backup-日期時間.json`，在手機的「下載」資料夾）。
請把這個檔案存到雲端硬碟、LINE Keep，或寄給自己。有「分享備份檔」時可直接分享到雲端硬碟；也可「複製備份文字」貼到筆記。
App 會在「從沒備份」或「超過 7 天沒備份」時，在首頁顯示不擋操作的提醒（可按「稍後」延後一天）。

### 還原（換手機／資料不見）
1. 打開網站（新手機請先照第 2 節安裝）。
2. 首頁按「還原備份檔」，或到 設定 →「還原備份（完整取代）」。
3. 選備份檔 → 看預覽（食物、套餐、紀錄筆數；本機會被取代的紀錄會警告）。
4. 建議按「先下載目前備份」，再勾「我了解…」→「確認完整取代」。
5. 同一份備份還原兩次，結果完全一樣，不會倍增。
6. 還原前 App 會自動留一份「匯入前快照」；按錯了，設定 →「復原到上次匯入前」可以救回。

### 只搬食物庫（例如在電腦上整理食物）
設定 →「只匯出食物庫」→ 在另一個裝置 設定 →「匯入食物庫」。依代號新增或取代食物與套餐；本機其他食物、所有紀錄都不會動；預設不套用設定（可勾選套用）。

### 電腦偶爾使用
用電腦瀏覽器開同一個網址即可（資料另外存在電腦的瀏覽器）。要把手機的紀錄帶到電腦：手機下載完整備份 → 傳到電腦 → 電腦「還原備份」。反向亦同。**每次還原都是「完整取代」，不會合併**，所以以一台裝置為主即可。

## 6. 部署到 GitHub Pages（需要你操作；我沒有建立任何遠端資源）

網站只發布 `app/` 資料夾，由 `.github/workflows/pages.yml` 自動部署；部署前會先跑 `npm test`（包含「公開網站裡沒有私人資料」檢查）。

1. 在 GitHub 建立一個新的**公開**儲存庫（例如 `kouda-app`；免費帳號的 Pages 需要公開儲存庫）。儲存庫裡只有程式，沒有你的食物清單。
2. 在本資料夾（`kouda-app`）執行（把網址換成你的）：

```bash
git init -b main
```

```bash
git add .
```

```bash
git status
```

   確認清單裡**沒有** `private/`、`.json` 備份檔或 Excel（`.gitignore` 已擋住，測試也會檢查）。然後：

```bash
git commit -m "每日飲食扣打 V1"
```

```bash
git remote add origin https://github.com/你的帳號/kouda-app.git
```

```bash
git push -u origin main
```

3. GitHub 儲存庫頁面 → **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。
4. 到 **Actions** 分頁等「Deploy to GitHub Pages」變綠色（約 1–2 分鐘）。網址是 `https://你的帳號.github.io/kouda-app/`。
5. 手機打開這個網址，照第 2 節匯入並安裝。

之後改程式：執行 `npm run stamp` 與 `npm test`，再 `git push`，網站自動更新。已安裝的手機打開時會在首頁出現「已有新版本 → 重新載入」，按了才換新版；**更新不會動到手機裡的食物與紀錄**（已實測）。

## 7. 資料與隱私

- 公開網站（`app/`）只有程式，沒有任何食物清單、體重、備份。測試會掃描 `app/` 確認。
- `private/`（含 `seed.json`）、`kouda-backup-*.json`、`kouda-library-*.json`、`*.xlsx` 都在 `.gitignore`，不會進 Git。
- 沒有帳號、沒有追蹤、不呼叫任何外部服務；與 ChatGPT 的來往完全是你自己複製貼上。
- 匯入的檔案、GPT 貼上的文字，顯示時一律跳脫，不會被當成 HTML 執行。

## 8. 記帳規則（程式強制）

1. 紀錄建立時複製食物當下的名稱、熱量、蛋白質、來源（快照）；之後改食物庫不影響舊紀錄。
2. 套餐加入時展開成多筆、共用 `group_id`；套餐本身不計入總數，也不允許另存總熱量。
3. 蛋白質未知一律是 `null`，不算 0；另外計「未知項數」。
4. `diet_day` 在建立時寫入，預設 05:00 換日；之後改換日時間不搬動舊紀錄。
5. 每個飲食日第一次使用時存下當時的目標。**補記一個還沒有目標的舊日子：用「當時的預設目標」建立並保存**；之後改預設不回寫已建立的日子。改目標時可選擇「同時套用到今天」。
6. 剩餘熱量可以是負的，畫面顯示為「已超過目標 N kcal」。
7. 所有寫入在單一交易內完成並依序排隊（連點、雙擊不會互相搶資料）；寫入失敗時畫面資料不會被改一半。
8. 匯入前先檢查格式與引用（套餐引用的食物、快捷格引用的項目都必須存在）；有錯整個不匯入。

### 資料來源類型
`label` 包裝標示｜`recipe_calc` 固定配方｜`legacy_estimate` 舊估算｜`gpt_estimate` GPT 估算｜`rough` 粗估。
`needs_confirm: true` 的是暫定值（目前：老樣子拿鐵 245 kcal／蛋白質未知；南加州 470 kcal／42 g），首頁會標「待確認」。
