## 5. 與 V1 的資料相容性

- **沒有 schema 變動**：IndexedDB 仍是 `kouda-v1`、版本 1，五個資料表（foods／presets／days／entries／meta）與主鍵不變；`schema_version` 仍是 1；備份欄位與 V1 相同。V1.1 沒有新增任何必填欄位，所以**不需要遷移，也不需要回滾機制**。
- 有一個測試專門守住這件事（`compat.test.js`）：如果有人改了資料庫名稱、版本或資料表，測試會失敗。
- **真實升級實測**（瀏覽器、同一個網址）：
  1. 用 `main`（V1，快取版本 `b03ec6e1a6`，就是你手機上現在這一版）建立資料：匯入食物庫、兩天的紀錄（單品、套餐、整餐模板、粗估、GPT 估算）。
  2. 換成 V1.1 的程式，同一個網址重新開啟：V1 先從快取跑起來，出現「已有新版本 → 重新載入」。
  3. 按「重新載入」後：版本變 1.1.0、舊快取自動刪除、資料庫仍是 `kouda-v1` 版本 1；**食物、套餐、每日目標、設定、9 筆紀錄逐欄位相同、每天的總熱量與蛋白質相同**。
  4. 在升級後的資料上使用減號、撤銷、複製：正常，舊紀錄不變。
- V1 備份 → V1.1 還原、V1.1 備份 → 格式與 V1 欄位相同，皆有自動測試。

## 7. 部署與更新方案（需要你同意後才進行）

目前一切都**只在本機分支**，網站（`main`）完全沒動。

1. 你審核這份報告與分支（ZIP 內含 `.git`，裡面就是 `feature/v1.1-ux` 的 commit（核心與狀態層、畫面、文件））。
2. 推送**分支**（不會部署，因為部署流程只在 `main` 被推送時觸發）：
   ```bash
   git push -u origin feature/v1.1-ux
   ```
   然後可以在 GitHub 開 Pull Request 給自己審。
3. 同意之後才合併到 `main`（網頁上按 Merge，或 `git checkout main && git merge feature/v1.1-ux && git push`）。合併會觸發 Actions 自動測試並部署，網址、manifest、PWA 範圍都不變。
4. 手機上已安裝的 App 打開時會看到「已有新版本 → 重新載入」，按了就升級，**不需要重新安裝，IndexedDB 資料不動**。
5. 萬一要退回：在 `main` 上 revert 那次合併再推送即可；因為資料格式沒有變，退回 V1 不會有資料問題。

## 8. 已知限制與設計取捨（沒有未完成的必要功能）

- 「最近／常吃」不列出已經在首頁快捷格上的項目（這個入口是用來找回快捷格以外的東西）；若快捷格已經涵蓋你所有常吃的，這裡會是空的。
- 複製舊餐預設**不勾選**任何項目（避免誤複製），有「全選」。
- 套餐的組成份數、名稱重複的處理：同名或相同內容的套餐會直接擋下，不提供「仍要建立」。
- 減號只動 `origin=food` 且不在群組內的紀錄；「存成快捷」的粗估／GPT 食物，其紀錄不能用卡片減號減（請用左滑刪除或編輯）。
- 清單的列不做拖曳排序；刪除用高度收合動畫（沒有逐列位移的 FLIP 動畫）。
- 新的 `:has()` 樣式（卡片按下縮放、左滑底色隱藏）在較舊的 WebView 不會生效，但功能不受影響（只是少了縮放、紅色底可能在邊緣露出細線）。
