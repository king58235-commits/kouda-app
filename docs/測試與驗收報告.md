## 3. 測試過程中發現並修正的問題

| 問題 | 修正 |
|---|---|
| GPT 解析會把名稱裡的全形「＋」「（」轉成半形（改掉使用者看到的名稱） | 名稱保留原樣，只有數字欄位做全形轉換 |
| 熱量寫成「300 kcal（半份 150）」會被當成 150–300 的範圍 | 括號內有數字一律拒絕並說明 |
| 粗估紀錄的「一般」數值在選偏多時被存錯 | 範圍的中間值與實際採用值分開存 |
| 食物編輯的「偏少／偏多」欄位切成單品後仍顯示（`hidden` 被 CSS 蓋掉） | 加入 `[hidden]{display:none!important}`，已重測 |
| 第一次安裝離線快取時，頁面會自己重新整理（可能打斷操作） | 只有按「已有新版本→重新載入」才換版 |
| 同一時間記入的套餐項目，清單順序隨機 | 套餐展開的每一項時間差 1 毫秒，順序固定 |
| 頂端「食物庫」按鈕換行；數量徽章壓到名稱；提醒橫幅佔太多高度 | 版面調整，已重測 |
| 在不同電腦（CRLF／LF）算出的離線快取版本不同，會讓 GitHub 上的檢查失敗 | 版本雜湊忽略換行；加 `.gitattributes` 固定 LF |

另有幾個是測試本身預期寫錯（時間戳相同造成排序不確定、蛋白質未知數量算錯等），已更正測試，程式行為沒有改。
